RetroPLC BuildHost migration to RetroPLC_BuildEnvironment

Implementation
- BuildHost resolves and validates an installed Pixi workspace, then runs its West commands from that workspace. Standard output carries JSON progress, results and errors. Standard error carries compiler output and diagnostics.
- The async process runner preserves process exit codes, uses ArgumentList, drains both streams and terminates the process tree on cancellation. Startup failures, malformed JSON and missing results are reported to the Build pane.
- Download requires a successful build and validated artifacts before starting upload. Device verification is available through VerifyFirmwareAsync, with confirmation as an explicit opt-in. An already-installed image and an update request are both successful outcomes. Only the former establishes that the matching image was already active.
- Generated output is validated in Build/Generated. Firmware artifacts are validated in Build/Zephyr/app/zephyr. New builds do not publish copies to Build/Artifacts.
- The existing dock shows live output on the Avalonia UI thread and preserves operation completion notifications. The interactive terminal opens a PTY-backed Pixi shell. Library import keeps its separate terminal behavior.
- The pre-existing debug monitor prefers Build/Generated/debug_map.json and falls back to its legacy map when the canonical map is absent. The debug monitor still uses its existing standalone mcumgrctl. Firmware operations have no standalone mcumgrctl dependency.

Configuration
- RETROPLC_BUILD_ENVIRONMENT selects the installed workspace root. The default is RetroPLC_BuildEnvironment beside the application. The workspace must contain pixi.toml and pixi.lock.
- RETROPLC_PIXI_EXECUTABLE optionally selects Pixi by path or name. Otherwise Pixi resolves from PATH. Relative paths resolve from the IDE process working directory.
- Machine commands run with PIXI_NO_INSTALL and PIXI_LOCKED. The interactive terminal uses pixi shell --no-install --locked.
- Configure device.serialPort in the project's project.json. Optional settings are device.baudRate (115200) and device.timeoutMilliseconds (10000). Alternatively, device.udpHostname and device.udpPort (1337) select UDP for compatible Runtime firmware. No device is selected automatically.

Command mapping
All machine commands use pixi run --quiet west and an absolute project path.
- Verify => plc-transpile
- Build / Rebuild => plc-build
- Clean => plc-clean
- Download => plc-build, then plc-upload with the configured transport
- Firmware verification => plc-verify with the configured transport and optional --confirm

Compatibility and remaining limitations
- The installed plc-transpile does not pass project Libraries to its compiler helper. Verify and firmware builds report the limitation when Libraries contains .stlib files. BuildEnvironment needs to pass the project library directory.
- The installed plc-build fixes its board, workspace, SDK, Runtime application, build paths, sysbuild and pristine policy. Unsupported legacy build overrides are reported. BuildEnvironment would need to expose the corresponding settings before the IDE can forward them.
- BuildEnvironment's Zephyr-generated compiler invocation needs quoting fixes for spaces in project paths. C# and Pixi preserve the path correctly, and live transpilation succeeded with spaces. Firmware compilation needs a space-free path with the tested revision.
- Clean delegates to West, which removes Build/Generated and Build/Zephyr. Old Build/Artifacts directories can remain.
- Firmware verification and explicit confirmation are available through the BuildHost API. The existing IDE Verify action remains a source transpilation action.
- Physical upload, reboot, confirmation, UDP transport and interactive GUI behavior were not exercised live. No external repository was changed. No commits or pushes were made.
