Compilation
  BuildHost uses one managed Node invocation and one STruC++ compile() call
  for Build, Rebuild, Verify, and Download preparation. The helper uses
  native ST/IL discovery, including nested sources and excluding ProjectFiles/Tests.
  The helper loads explicit project .stlib directories with discoverStlibs().
  The IDE still requests no default bundled libraries. A deterministic MD5 of
  the sources, loaded libraries, and compiler package version populates the map.
  It stages the complete output set before replacing Build/Generated.
  Successful replacement removes obsolete translation units and old headers.
  Compilation and library failures preserve the previous generated set.

Outputs and Runtime
  Build/Generated contains generated.hpp, native named C++ units,
  generated_debug.cpp, and the native v2 debug_map.json.
  The Runtime already globs generated C++ files. Its scan loop and pointer
  table now share one global g_config. A compile-time declaration checks the
  configuration class and Zephyr linker options retain the table symbols.
  BuildHost validates the map before starting west and checks it again before
  publishing. It stages the firmware and map together under Build/Artifacts.
  Failed or cancelled builds preserve the last successful published pair.
  Verify updates generated files only. Download still uses mcumgr after
  a successful build. Setup applies the Runtime patch idempotently and checks
  that the compiled Node API exists. No STruC++ or west backend files changed.
